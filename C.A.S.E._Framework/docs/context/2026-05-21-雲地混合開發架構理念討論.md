## 第一輪：概念驗證與架構解構 (Architecture & Concept)

**參與角色：**

-   **系統架構師 (System Architect)：** 專注於雲端與本地端資源的調度與協作。
    
-   **流程治理專家 (Process Governance Expert)：** 檢視任務分派、權責劃分與防呆機制。
    
-   **資安與隱私專家 (InfoSec Expert)：** 關注資料流向與機密性。
    

**【討論過程】** **系統架構師：** 這個架構最精妙之處在於「算力與智力的解耦」。雲端模型（如 GPT-4, Claude 3.5）擁有強大的 Zero-shot 推理與規劃能力，適合擔任「立法院」制定 roadmap 與拆解 task queue。本地模型（如 Llama 3 8B/70B 等）雖然智力有上限，但只要工作包（Recipe）定義得夠精確，就能穩定執行。 **流程治理專家：** 同意。將每一個工作任務包裝成包含「小憲法（指引）、食材（資料）、驗收方法、進度紀錄點」的獨立單元，這在軟體工程上稱為無狀態（Stateless）的高內聚設計。這確保了即使本地模型中斷，下一個接手的模型也能無縫接軌。但潛在風險是：雲端模型訂定的「驗收方法」，本地模型是否具備足夠的「評估能力」來自我驗證？ **資安與隱私專家：** 從執法與調查的角度來看，這完美解決了痛點。敏感的「食材（目標資料）」完全不需要上傳雲端。雲端只負責生成「處理菜譜」，本地端才將「菜譜與食材」結合進行運算。我們確保了資料邊界（Data Boundary）。

**【本輪結論】** 架構方向具備高度可行性與安全性。**自動推進至下一輪：深入探討 Task Queue 的設計與本地執行的技術瓶頸。**

## 第二輪：工作包設計與本地執行限制 (Execution & Bottlenecks)

**參與角色：**

-   **多智能體協作專家 (Multi-Agent Expert)：** 專注於 Task Queue 的流轉與 Agent 間的通訊。
    
-   **本地模型微調/部署專家 (Local Edge AI Specialist)：** 熟悉 Ollama、llama.cpp 等本地運行限制。
    
-   **QA 測試工程師 (QA Engineer)：** 專注於驗證機制與異常處理。
    

**【討論過程】** **多智能體協作專家：** Task Queue 必須具備動態調整能力。本地模型在執行時，如果發現「新線索」或「異常」，它生成的 feedback 必須能回傳給雲端模型，讓雲端模型「修法」或「新增 task」。這是一個閉環（Closed-loop）系統。 **本地模型微調/部署專家：** 這裡有個硬傷需要面對——Context Window（上下文窗口）與 Instruction Following（指令跟隨）能力的限制。工作單如果包含太複雜的「小憲法、食材、驗收、紀錄指引」，本地 8B 級別別的模型可能會發生「注意力遺忘」，只執行了動作，卻忘記去指定檔案報到紀錄。 **QA 測試工程師：** 對，所以驗收機制不能只依賴本地模型的自我檢查（Self-Reflection）。我建議在本地端建立一個「雙角色機制」：一個本地 Agent 負責「執行（Doer）」，另一個較小但邏輯嚴密的本地 Agent 專門負責「驗收（Checker）」。如果 Checker 判斷 Doer 失敗，就退回重做；若連續失敗三次，則將該 Task 標記為 Error，拋回 Task Queue 讓雲端重新拆解成更細的步驟。

**【本輪結論】** 單一本地模型處理過於複雜的 Task Package 容易失焦。需引入「本地執行者+本地驗收者」的雙軌制，並設立「重試上限機制」以避免死循環。**自動推進至下一輪：探討脈絡紀錄與記憶管理機制。**

1.  **Draft/Log.md (短期記憶)：** 紀錄當下這一步做了什麼、結果如何。
    
2.  **State/Progress.json (狀態機)：** 嚴格的鍵值對，讓程式邏輯可以直接讀取哪些 Task 已完成、哪些失敗。
    
3.  **Vector DB (長期記憶)：** 處理過的大量文本與洞察，供後續 RAG 檢索。 **高科技犯罪調查實務專家：** 完全同意。就像我們辦案一樣，會有「偵查日誌（時間軸）」、「證據清單（結構化數據）」和「卷宗（完整脈絡）」。雲端模型在分配下一個任務前，只需先調閱「偵查日誌」與「證據清單」的摘要，就能確保下一步的「法律（Roadmap）」不會偏離「憲法（核心目標）」。
    

**【本輪結論】** 脈絡紀錄必須分層管理（短期日誌、結構化狀態、長期向量記憶），不能僅依賴單一純文本檔案，以確保雲端模型能精準掌握進度且不超出 Token 限制。

## 第一輪：沙盒邊界與安全防護設計 (Security & Sandboxing)

**參與角色：**

-   **零信任架構專家 (Zero-Trust Architect)：** 專注於權限隔離與損害控制。
    
-   **容器化與作業系統專家 (Containerization Expert)：** 負責實體檔案系統的隔離。
    
-   **Agentic 工具設計師 (Tooling Designer)：** 負責規劃 Function Calling 的介面。
    

**【討論過程】** **零信任架構專家：** 讓本地模型直接執行 `mkdir`, `read`, `write` 是個雙面刃。最糟的情況是模型發生幻覺（Hallucination），寫了一個無窮迴圈，或者誤刪了 `/00_Constitution/`。我們必須實作「路徑鎖定（Path Jailing）」。 **容器化與作業系統專家：** 強烈建議這個 Coding Agent 必須在 Docker 容器內運行。即使它有權限呼叫 CLI 指令，它的 `root` 也是被閹割過的。另一個作法是，提供給 Agent 的工具不是原生的 bash 指令，而是經過我們封裝的 API。 **Agentic 工具設計師：** 同意。我們不該給它 `os.system("rm -rf ...")` 這種無差別工具。我們應該設計特定目的的工具，例如 `read_file(filepath)`，並在工具底層加上檢查：只要 `filepath` 包含 `00_Constitution` 或 `01_Roadmap`，並且是執行 `write` 動作，底層就直接回傳 `Permission Denied: System Constraint`，讓 Agent 知道它越界了，並強迫它重新思考。

**【本輪結論】** 絕不能給予 Agent 毫無限制的底層終端機存取權。必須透過「受控工具 API (Controlled Tool API)」取代原生 bash，並在工具底層實作路徑與讀寫權限的硬限制。**自動推進至下一輪：具體工具清單 (Tool Schema) 的設計。**

**【本輪結論】** 工具設計需奉行「極簡主義與專用化」，將更新狀態等關鍵動作獨立為專用工具，並強制記錄所有工具呼叫的軌跡。**自動推進至下一輪：錯誤恢復與狀態回滾機制。**

### 3\. ⚙️ 執行細則與戰術層（由「本地端安全 AI」擔任）

-   **角色：** 基層調查員 / 承辦人員。
    
-   **職責：** 本地 AI 雖然智力不如雲端，但優點是資料絕對不會外流（斷網也能跑）。它不需要自己做大計畫，只需要打開雲端做好的「工作任務包」，照著裡面的指引（菜譜），處理目標資料（食材），做完後寫下報告，並更新進度。

-   **第三層（本地 AI）是量子視角（微觀世界）：** 任務資料夾裡充滿了未知的原始資料（疊加態）。本地 Agent 進入資料夾，運用其智力進行觀測與運算，最終將混亂的資料「塌縮（Collapse）」成一份結構化的確鑿證據（Output Artifact）。在這個量子態裡，Agent 不需要、也不應該去管宏觀宇宙長怎樣，它只要專注把眼前的波函數塌縮即可。
    

**高科技犯罪偵查專家：** 結合我們的實務，這就像是「專案指揮所」**與**「現場採證 / 數位鑑識實驗室」的差別。 指揮所（第二層）要畫出犯罪組織的關聯圖（Roadmap），並決定「要湊齊哪些證據才能移送地檢署（全案驗收）」。而實驗室（第三層）的鑑識人員不需要知道整個販毒網絡長怎樣，他只負責針對這台扣押的手機（單一任務包），萃取出 Telegram 裡的通訊紀錄（微觀萃取與單點驗收）。

**系統架構師：** 從檔案驅動（File-Driven）的角度來看，這意味著我們必須在 `/01_Roadmap/` 目錄下新增全域控制文件。 雲端 AI 在一開始不僅要生成 `/02_Task_Queue/`，還要生成一份 `Global_DoD.md` (Definition of Done，全案驗收標準)。 當所有量子層級的 Task 都標記為 `[DONE]` 時，系統會啟動「全域聚合階段（Global Aggregation）」：將所有微觀任務的 output 統整起來，再次呼叫第二層的雲端 AI，讓它站在宏觀角度審視：「這些微觀證據拼湊起來，是否達到了 `Global_DoD.md` 的標準？」如果達標，全案結束；如果發現拼圖少了一塊，第二層就會生成「新的 Roadmap (Phase 2)」與新的工作包，重新發包給微觀層。

**【本輪結論】** 明確確立第二層的「宏觀規劃與全域驗收」職責，與第三層的「微觀執行與單點塌縮」職責。這不僅解決了 AI 的幻覺問題，更賦予了系統動態迭代（Dynamic Iteration）的能力。
